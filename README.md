# 游戏聊天栏翻译器

框选游戏聊天栏，按一个热键，外文就变成中文显示出来。

> **用之前知道一下**
>
> 「回话」那部分会**往游戏里模拟按键** —— 把译文一个字一个字打进聊天框。
> 这是自动化特征。因为发条聊天消息被封的情况极少，但确实不为零，
> **风险自担**。
>
> 别拿它改成游戏宏 —— 那性质就完全不一样了，而且烧的是你自己账号。
>
> 本程序按 GPL-3.0 发布，详见 [LICENSE](LICENSE)。

```
按下 Ctrl+Alt+T
   ↓
截取你框选的区域（约 5 毫秒）
   ↓
直接发给 DeepSeek 的视觉模型
   ↓
悬浮窗逐字显示中文
```

没有 OCR 环节：`deepseek-flash` 能直接看图读出文字并翻译，所以不需要装
PaddleOCR 之类的重型依赖，整个项目只用四个纯 Python 库。

---

## 安全边界

这个工具**只截屏幕、只向 DeepSeek 发 HTTP 请求**：

- 不注入游戏进程
- 不读写游戏内存
- 不修改游戏文件
- **不用键盘钩子** —— 热键默认走 `GetAsyncKeyState` 轮询，就是一个普通的
  查询 API（"这个键现在按着没"）。钩子是万不得已才用的最后手段，得自己去开
- **只在你要回话时模拟按键** —— 把译文逐字符打进聊天框，和注入、读内存
  完全是两回事。但它确实是自动化特征，心里没底就把「发送前先看一眼」打开，
  至少每一条发出去之前你都过目了

钩子那条是刻意的。网上多数方案用 `pynput` 之类的库装全局键盘钩子
（`WH_KEYBOARD_LL`），而 EAC、BattlEye、Vanguard 这类内核级反作弊**会检测
甚至封禁键盘钩子** —— 它本来也是键盘记录器的典型特征。轮询则没有这个问题，
反作弊视角下跟"读一下现在几点"差不多。

顺带一提：Discord、MSI Afterburner 那种能显示在游戏画面上的覆盖层，
是靠注入游戏的 DirectX 渲染管线实现的——效果好，但正是反作弊盯的东西。
本工具不做这件事，代价就是下面这条限制。

---

## ⚠️ 游戏必须用「窗口化」或「无边框窗口化」

真·独占全屏（Exclusive Fullscreen）下有两个硬限制：

1. **截图会截到黑屏** —— 独占全屏的画面不在 GDI 能读到的缓冲里
2. **悬浮窗盖不上去** —— 任何非注入式的窗口都会被全屏游戏压在下面

这是 Windows 用户态程序的物理限制，绕不过去。

**解决办法：进游戏设置，把显示模式改成「窗口化」或「无边框窗口化」。**
现代游戏基本都支持，画面体验几乎没差别，还能秒切出去看攻略。

## 安装

需要 Python 3.10 以上（本项目在 **3.14.6** 上开发并验证）。

```bash
git clone <仓库地址>
cd game-translator
pip install -r requirements.txt
```

四个依赖全是纯 Python，没有 C 扩展，装起来不会跟环境打架。

## 配置 API key

首次运行会自动生成 `config.json`。编辑它，填上你的 key：

```json
{
  "api_key": "sk-你的key",
  ...
}
```

或者设环境变量（**优先级更高**，适合不想把 key 写进文件的情况）：

```bash
set GCT_API_KEY=sk-你的key
```

key 去 https://platform.deepseek.com 申请。

> `config.json` 已经在 `.gitignore` 里。**分享这个项目给别人时，
> 记得别把 config.json 一起给出去。**

### 想用别家 AI 也行

主界面「API Key」那一页底下有「换个 AI」两栏：**接口地址**和**模型名**。
默认是 DeepSeek，填上别的就能换。

**两个前提**，缺一不可：

1. **对方提供的是 OpenAI 兼容接口** —— 也就是 `/chat/completions` 那个
   `messages` 格式。市面上大部分都是（OpenAI、通义、智谱、Kimi、
   硅基流动、本地 Ollama……）。Claude 不是，接不了。
2. **你选的模型得能看图** —— 本工具是**把截图直接丢给模型**，跳过 OCR
   就是它的核心设计。填个纯文本模型上去，它会读不出图，或者干脆报错。

```
接口地址   https://api.openai.com/v1          ← 该带 /v1 就带上，别省
模型名     gpt-4o                             ← 或 qwen-vl-max、glm-4v 等
```

> **不会填就别动。** 留默认的 DeepSeek 就行 —— 它对中文游戏聊天这个场景
> 够用，而且便宜。这两栏是留给知道自己在干什么的人的。
>
> 顺带一提，之前这里有个 bug：代码会把地址结尾的 `/v1` 悄悄剥掉。
> DeepSeek 带不带都行所以没露馅，但 OpenAI 的端点**必须**带 `/v1`，
> 剥了就连不上。现在改成原样拼接了。

## 使用

**双击 `启动.bat`** 就能打开（没有黑窗口，不会闪控制台）。

首次打开会先弹一个输入 API key 的框，填完进入主界面：

1. 点「框选区域」→ 屏幕变暗，拖动鼠标框住聊天栏
2. 松手后**不会立刻确认**——先看清楚框得对不对
3. `Enter` 确认，`Esc` 或右键重来
4. 点「最小化到后台」，切回游戏按热键

主界面是**左侧导航 + 右侧内容**：

```
┌──────────┬────────────────────────┐
│ API 密钥 │                        │
│ 聊天区域 │                        │
│ 回话     │    当前页显示在这里     │
│ 术语表   │                        │
│ 记录     │                        │
│ 热键     │                        │
└──────────┴────────────────────────┘
```

「聊天区域」那一页里管着**框选区域**、**翻译显示位置**，
以及三个开关：「聊天输入框」（给 `Ctrl+Alt+I` 用的）、
「画面没变就跳过」（**默认关**，见下面「两个开箱即用的判断」）、
「翻译说话人的名字」。

改完立即生效，下次打开还记得。

想在命令行跑（有日志输出，方便排查）：

```bash
python main.py
```

**出错了看不到信息？** 双击 `调试启动.bat`，错误会留在窗口里不消失。

## ⚠️ 热键在游戏里按了没反应？换「工作方式」

主界面「热键」那一节有**三种工作方式**，**默认是「轮询」**。
这不是调着玩的，是游戏的反作弊会拦热键 —— 按下面的顺序往上试：

| 工作方式 | 原理 | 什么时候用 |
|---|---|---|
| **轮询**（默认） | `GetAsyncKeyState`，不停问"这个键按着没" | **默认就用这个**。不挂钩子，对反作弊最不敏感 |
| 标准 | `RegisterHotKey`，向系统登记组合键 | 桌面和普通程序用。**很多游戏会拦它**（LOL 就是） |
| **键盘钩子** | `WH_KEYBOARD_LL`，挂在系统键盘消息链上 | 轮询也不行时才用。**它是键盘记录器的典型特征，有被反作弊盯上的风险** |

### 实测结果

| | 国服 LOL（WeGame / SGuard） | 国际服 LOL |
|---|---|---|
| 标准 | ❌ | ❌ |
| 轮询 | ❌ | ✅ |
| 键盘钩子 | ❌ | ✅ |

**腾讯的 SGuard 三层全堵**（`SGuard64.exe` 还有自我保护，任务管理器结束不掉），
**Riot 只堵了「标准」这一层**。所以国服可能真的没辙，国际服没问题。

> **优先用「轮询」**——它和「钩子」都能用，但轮询只是一个普通的查询 API，
> 反作弊视角下和"读一下现在几点"性质差不多；钩子则会被安全软件当成 keylogger 特征。

### 热键

| 默认组合键 | 作用 |
|---|---|
| `Ctrl+Alt+T` | 翻译聊天栏（看别人说啥） |
| `Ctrl+Alt+E` | 弹小框说中文（翻好自动发出） |
| `Ctrl+Alt+I` | 游戏里打了中文，就地翻掉替换 |
| `Ctrl+Alt+R` | 重新框选 |
| `Ctrl+Alt+H` | 显示 / 隐藏主窗口 |
| `Ctrl+Alt+Q` | 退出程序 |

**六个都能改**：主界面「热键」页每一行末尾都有「修改」，点一下直接按你想用的键。

- 加不加修饰键随你 —— `Ctrl+Alt+T`、`Ctrl+F9`、`F9` 都行
- **F1–F12 可以单按**（推荐，不会影响打字）
- 字母和数字也能单按，但那会把那个键从游戏和日常打字里"吃掉"，
  对话框会提醒一句但还是让你用
- 同一个组合只能给一个功能用：设成别人在用的，会当场提示
- 被别的程序占了（游戏、截图工具、录屏软件都爱抢），会提示并退回默认值

换完立即生效，不用重启。

> **⚠ 设置的时候先把输入法切到英文。**
> 中文标点模式下，输入法会接管 `;` `'` 这类符号键（把它们转成全角标点），
> 系统收到的就已经不是原来那个键了 —— 表现是按键没反应，
> 或者莫名其妙变成方向键之类的怪东西。切成英文标点就正常了。
>
> 这个只影响**设置热键的时候**。热键一旦注册成功，
> 它由系统直接投递，跟输入法是什么状态无关。

如果新热键被别的程序占着（输入法、Discord、NVIDIA 这些很爱占），
会提示被占用并**自动退回默认的 `Ctrl+Alt+T`**，不会让你没热键可用。

**关掉窗口 = 退出程序。** 想让它继续在后台待命、随时按热键翻译，
点「最小化到后台」（或者按 `Ctrl+Alt+H`），别点右上角的 ✕。

想换组合键，改 `config.json` 里 `profiles.default.hotkey`，格式是
`<ctrl>+<alt>+t` 这种。支持 `<ctrl>` `<alt>` `<shift>` `<win>` 加
字母、数字、`<f1>`~`<f12>`。

## 监视模式（可选）：不用按热键

打开后程序就不等热键了 —— 它隔一会儿自己看一眼聊天栏，有新消息就翻出来。
「聊天区域」页里有开关和间隔。

**但这条只对一部分游戏成立。** 判据是"整块截图有没有变化"，实测数据摆在这儿：

| 聊天框 | 画面没变时 | 来一条新消息时 |
|---|---|---|
| **不透明** | 0.000 | 0.775 ~ 1.629 |
| **半透明**（LOL 那种） | 背景平移 1.3 ~ 1.7 | **0.34** |

第一行分得干干净净 —— 能用。第二行**背景动的幅度比新消息还大**，判据会一直
误报成"有新消息"，每条都白花一次 token。**LOL 这类半透明聊天框就别开了。**

**开之前先想清楚你的聊天框是哪种**：底下的游戏画面会不会透过来、会不会动。
一个土办法：框好区域后开着监视看几秒悬浮窗 —— 要是它隔一会儿就冒一次
「（没有新消息）」，说明判据在误报，关掉。

> 开监视时程序会顺手打开「画面没变就跳过」—— 那是省钱的前提。
> 没它的话，就是每隔一秒实打实烧一次 API。

## 省 token 的两个机制

**① 画面没变就不调用（默认关着）**

按下热键时会先跟上一张截图比一比，差异低于阈值就直接提示"（没有新消息）"，
一次模型调用都不发。

**但它默认是关的。** 判据是"整块画面像素没变"，而聊天框多半半透明
（LOL 就是），底下画面一直在动 —— 判据会频繁误判成"有新消息"，
等于每次白比对一遍，省不下多少还多一层不确定性。想省再打开。

**它还是「监视模式」的前提** —— 开监视时程序会自动把它打开，
不然就成了每隔一秒实打实烧一次 API（见上一节）。

> 这段判据本身没问题：另一款不透明聊天框的游戏上实测，画面没变时差异
> 是 0.000、来了新消息是 0.775~1.629，分得很开。**是半透明把这个判据废掉的。**

**② 只显示新来的消息**

每次翻译后，工具会记下**这句原文**（不是译文——同一句 `hello`
可能翻成"你好"也可能"您好"，拿译文当标识会误判）。下次整块图重新翻译时，
已经见过的原文会被挡掉，**悬浮窗只出现新消息**。

重新框选区域时会重置这些记忆（换了个地方看）。

### 关于提示词改成了 JSON

为了让模型把**原文**也返回，提示词现在要求它输出：

```json
[{"user": "Tom", "source": "gg wp", "translation": "打得不错"}]
```

你如果自己改过 `config.json` 里的 `prompt`，**那份不会被覆盖**——
但也就享受不到按原文去重的好处了。想用新格式，把 `prompt` 整段删掉，
程序下次启动会自动填回新版默认值。

> 模型偶尔不按格式返回（加了 markdown 包裹、前后带解释文字）。
> 解析器有容错；实在解析不了就退回按行对比的老办法，不会什么都显示不出来。

## 说给外国人听

两条路，看哪个顺手：

### 一、弹小框 —— `Ctrl+Alt+E`

游戏里按一下，屏幕下方弹出一个小输入框：

```
┌────────────────────────────────────┐
│ 打野来上路                          │  ← 在这里打中文
│ 回车发送 · Shift+回车换行 · Esc 取消 │
└────────────────────────────────────┘
```

回车 → 翻好 → 小框自己关掉 → 游戏收到并发出。**全程不用切窗口。**

### 二、游戏里打字再翻 —— `Ctrl+Alt+I`

照着平时那样在聊天框里打中文，然后按 `Ctrl+Alt+I`：
程序读出那行字 → 翻好 → 替换掉原来的中文 → 发出去。
打字全程在游戏里，输入法和候选词都是原生的。

需要先在「区域」页**框一个「聊天输入框」区域**（只框你打字那一条，
不是整个聊天栏）。

### 翻成什么语言

「回话」那一页顶上能选：**日文 / 英文 / 韩文 / 繁体中文**，日服选日文。

术语表**自动倒过来用**，不用另建一份：

- 你写「辛苦了」→ 发 `おつ`，写「打得好」→ 发 `上手い`
- 一个中文对上多条术语时（「打得好」也可以是 `wp`），**翻日文优先挑日文说法**，
  翻英文优先挑英文缩写
- 翻非日文时，日文条目整个排除 —— 不会出现"要翻成英文却吐出 `おつ`"

### 翻完怎么办：三档

「回话」页最上面能选：

| 选它 | 行为 | 什么时候用 |
|---|---|---|
| **直接发进游戏**（默认） | 翻完自己发出去，你什么都不用按 | 最省事 |
| **先摆出来给我看一眼** | 把译文摆回小框，你再按一次回车才真发 | 模型偶尔翻错或多写一串，这样能拦下来 |
| **只放剪贴板** | 完全不碰游戏，译文进剪贴板你自己粘 | **不确定发送按键填得对不对时，选这个** |

「先摆出来」长这样：

```
┌────────────────────────────────────┐
│ jgはtopに来て                       │
│ 回车发出 · Esc 算了（不会发出去）    │
└────────────────────────────────────┘
```

再按一次回车才真发，`Esc` 就当没这回事。

> 「先摆出来」只管弹小框那条路。游戏里打字那条（`Ctrl+Alt+I`）翻完直接
> 替换发送 —— 那时候聊天框还开着，弹窗抢焦点有可能把里面已经打的字弄丢。

### 为什么不是复制粘贴

发按键而不是粘贴，一半是历史原因：**有些游戏（LOL 就是）有意禁用了外部
粘贴** —— 游戏里自己选中复制的能粘，从外面复制的一概粘不进去（官方说法
是防刷屏机器人）。在这类游戏里，`Ctrl+V` 这条路是堵死的，只能逐字符输入。

**别的游戏多半没这个限制**，所以「只放剪贴板」那一档对它们是好用的 ——
如果你玩的游戏能粘贴，用那档最省心，程序一根手指都不用碰你的键盘。

> 顺带说，发的是**按键**，不是注入 —— 本程序依然不碰游戏进程、不读内存、
> 不改文件，这条边界没变。

### 发送按键：按你的游戏改

回话功能是**往游戏里发按键**来完成的（开聊天框 → 打字 → 发送），
所以得先让它知道：你的游戏用哪个键开聊天框。

**界面上选就行**：「回话」页「发送按键」有两个下拉 ——
「开聊天框」和「发送」。绝大多数游戏都是回车，有的用 `T`、`Y`、`U`。
选完下面那两串序列会自动改好，点保存生效。

> **为什么这个非改不可**：如果程序以为聊天框是回车开的，而你玩的游戏
> 用的是 `T`，那发出去的 `enter` 就**不是**"开聊天框" —— 而是
> **在游戏里凭空按一下回车**，可能开出个菜单，或者触发别的功能。
>
> 拿不准就把「翻完怎么办」选成**只放剪贴板**，那样程序根本不碰你的键盘。

想更细地控制（比如开聊天框的键不在下拉里），下面还有「高级」两栏，
直接写按键序列：

| 写法 | 意思 |
|---|---|
| `ctrl+v` | 组合键（`+` 连起来） |
| `text` | 把译文**逐字符打进去** |
| `backspace*100` | 重复 100 次 |

左边那条是「开聊天框 → 打字 → 发送」，右边那条是「清空原文 → 打字 →
发送」。**用 `T` 开聊天框的游戏就写成 `t,text,enter`。**

> **为什么默认用逐字符输入而不是 `Ctrl+V`？**
> 实测 LOL 收单键（回车按得进去），但**不收 Ctrl 组合键** ——
> `Ctrl+V` 粘不进去，`Ctrl+A` 也选不中。所以默认走逐字符 Unicode 输入
> （序列里的 `text`），不碰剪贴板也不按修饰键。译文进剪贴板这一步照样保留，
> 万一打字失败，剪贴板里还有一份。
>
> 你玩的游戏要是能正常粘贴，也可以把 `text` 换回 `ctrl+v`，会快一些。

## 术语表

主界面左侧点「术语表」—— **左边是分类，右边是那个分类的词条**：

```
分类            词汇      译文              处理
英雄联盟  ◀     gg        打得不错          保持英文
CS2             ty        谢谢              翻译
自定义1         rush      快攻              保持英文
                mb        我的错            翻译
[＋][改名][删除]  [添加][编辑][删除][恢复默认]
```

### 为什么要分类

**按游戏分** —— 同一个词在不同游戏里意思可能完全不一样。
`eco` 在 CS 里是「经济局」，在别的游戏可能就是别的。

**同一时间只有一个分类生效**（左边高亮的那个），切过去就换一套。

> 注意是**按游戏分，不是按服务器或语言分**。
> 日服 LOL 和国服 LOL 是同一个游戏，术语表就该是一份。

- 点左边的分类切换，**立即生效**
- **＋ / 改名 / 删除** 管理分类
- 新建的分类是空的，自己往里加词

### 每条词的两种处理方式

| 处理 | 效果 |
|---|---|
| **保持英文** | 原样输出。`gg`、`rush` 这种中文玩家也认识的，翻了反而累赘 |
| **翻译** | 按「译文」那一列替换。`ty`、`mb` 这种国服不常用的，翻出来才看得懂 |

### 多义词：用 `/` 写多个译法

有些词在不同语境下意思完全不同：

- `ad` —— 既可能是**物理攻击**，也可能是**射手**
- `bot` —— 既可能是**下路**，也可能是**人机**

**这类词在译文里用 `/` 分隔多个含义**：

```
词汇   译文              处理
ad     物理攻击/射手      翻译
bot    下路/人机         翻译
```

模型会**结合上下文挑最合适的那个**。实测：

```
need more ad, buy damage items  →  需要更多物理攻击，买伤害装备
their ad is fed, bot is lost    →  对面射手发育太好了，下路没了
                                    ↑ 同一个 ad，两次翻得不一样
```

实在拿不准时，模型会保留原文，不会硬套一个错的。

**双击一行**就能改，或者用下面的按钮增删。改完**立即生效**
（相关缓存自动作废，不用手动清）。

**「恢复默认」只影响当前这个分类**，不会动别的分类。

### 默认给你两个分类

| 分类 | 内容 | 什么时候用 |
|---|---|---|
| **默认**（默认选中） | **空的** | 你自己往里加。不预设你玩什么游戏 |
| **英雄联盟** | 71 条现成的 | 玩 LOL 就切过去 |

**默认那个是空的** —— 这工具是给所有带聊天框的游戏的，一上来就替你选好一款
游戏、还塞七十来条术语，等于替你做决定。没玩那款游戏的人拿着
`gg` `おつ` 这些没用，甚至会干扰模型判断。

「英雄联盟」那份里有 `gg` `wp` `rush` `mid` `adc` `op` 这些保持英文的，
也有 `ty` `mb` `smurf` `int` `flank` 这些要翻的，还有一批日服固定说法
（`おつ` `よろ` `ナイス`）。

> **术语表对效果的影响比模型本身还大。** 队友的固定说法、你那个游戏特有的缩写，
> 写进去就会照着用。想给别的游戏建一份，左边「新增」就是了。

## 翻译记录

主界面左侧点「记录」—— **翻过的内容都在这儿，最新的在最上面**。
对局中想回看之前谁说了什么，翻这一页就行。

- **刷新 / 清空 / 复制选中**，也能「打开原文件」直接看 `history.jsonl`
- 只显示最近 400 条（文件里存的更多）
- 文件超过 1MB 会自动砍掉前半部分，不会无限涨

## 玩日服 / 其他语言

**任何语言都能翻** —— 提示词写的是「非中文文本翻译成简体中文」，不限源语言。

**术语表也按游戏分，不按语言分** —— 日服 LOL 和国服 LOL 是同一个游戏，
所以日文的固定说法**就在「英雄联盟」这一个分类里**：

| 词汇 | 译文 | 说明 |
|---|---|---|
| `おつ` / `乙` / `お疲れ` | 辛苦了 | 对局结束时的固定说法，直译走味 |
| `よろ` / `よろしく` | 请多指教 | 开局 |
| `ナイス` | 漂亮 | |
| `草` / `ワロタ` | 笑 / 笑死 | |
| `うますぎ` | 太强了 | |

日文句子本身模型直接就能翻，**术语表装的是那些「约定俗成」的说法**。

> **什么时候需要新建分类？** 换游戏的时候。比如你去玩 CS2，
> `eco` 在那边是「经济局」、和 LOL 的词不通用，就该建个 CS2 分类。

## 玩家名字

默认**不翻译**。名字多半是 ID、梗、谐音或者随便打的字符串
（`xX_DarkLord_Xx`），硬翻出来往往莫名其妙。

想看「`ウサギ` 是什么意思」时，在**「聊天区域」页勾上「翻译说话人的名字」**，
模型就会意译非中文的名字（`ウサギ` → 兔子），看不懂的 ID 仍然保持原样。

## 托盘图标

程序启动后任务栏右下角有个图标：

- **双击** → 显示主窗口
- **右键** → 显示窗口 / 翻译聊天栏 / 打中文回复 / 退出

最小化到后台之后，从托盘也能把窗口叫回来。

## 翻译显示在哪里

主界面上直接选，立即生效。也可以改 `config.json` 里的 `overlay.mode`：

| 值 | 效果 |
|---|---|
| `side`（默认） | 贴在聊天栏旁边，不遮挡原文，可以对着看 |
| `cover` | 半透明盖在原位置上，省地方但看不到原文了 |
| `corner` | 固定在屏幕角落，像字幕一样 |

其他可调的：`alpha`（透明度）、`font_size`、`width`（宽度）、
`max_height`（最高多少）、`auto_hide_sec`（多久没更新自动隐藏）。

悬浮窗可以直接用鼠标拖动。**拖过之后位置就固定了**，以后翻译都在你放的地方出现，
不会再弹回自动位置。想恢复自动贴聊天栏：把 `config.json` 里 `overlay.last_pos` 改成 `null`。

## 识别不准怎么调

**小字号游戏**（聊天栏字只有 12px 左右）——把 `capture.upscale` 改成 `2.0`：

```json
"capture": {
  "upscale": 2.0
}
```

截图先放大两倍再给模型，小字识别率会明显提升。代价是上传体积变成四倍
（也就从 2KB 变成 8KB，仍然可以忽略）。

**游戏黑话翻得不对** —— 加进术语表：

```json
"glossary": {
  "gg": "打得不错",
  "rush b": "冲B点",
  "你游戏里的黑话": "对应的中文"
}
```

术语表对实用性帮助比模型能力还大，建议玩什么游戏就往里加什么。

**提示词** —— `profiles.default.prompt` 可以整个重写。
注意里面有个 `{glossary}` 占位符，会被替换成术语表。

## 成本

按 DeepSeek 官方价格，一条消息的输入输出加起来**不到 1 厘钱**。

两个省钱机制已经在代码里了：

1. **上下文缓存** —— 提示词固定不变，每次请求前缀相同，DeepSeek 会自动命中
   硬盘缓存，输入价格降到 1/50。
2. **按图缓存** —— 相同画面不重复请求。聊天栏里 "hi" "gg" "lol" 和刷屏的
   重复率极高，实测能省掉一大半请求。

另外，工作日 9:00-12:00 和 14:00-18:00 是高峰时段，价格翻倍；
**晚上和周末都是空闲时段，自动半价。**

## 文件结构

```
启动.bat         双击这个
调试启动.bat      带控制台，出错时用

main.py           入口 + 线程编排
gui.py            主窗口界面
tray.py           系统托盘图标
config.py         配置读写
config.json       你的配置（含 API key，别外传）
winutil.py        Win32 底层（DPI、窗口样式、屏幕几何、剪贴板）
capture.py        截图 + 缩放 + JPEG 编码 + 内容 hash
selector.py       全屏框选界面
overlay.py        悬浮窗（只显示，不抢焦点）
quick_input.py    弹出来打中文的小输入框（要抢焦点，打完还给游戏）
hotkey.py         全局热键
translate.py      翻译层（provider 抽象 + DeepSeek + SSE 解析）
cache.py          翻译结果缓存
assets/logo.png   图标
history.jsonl     翻译记录（运行时生成）
调试发送按键.py    排查「译文发不进游戏」时跑这个
```

`translate.py` 里的 provider 是可插拔的。以后想加本地模型或别的后端，
写个类加上 `@register_provider("名字")`，配置里改一行 `provider` 就行，
其他代码不用动。

## 故障排查

**热键按了没反应**

- 启动时提示"已被别的程序占用" → 换个组合键（输入法、Discord、
  NVIDIA 这些都会占热键）
- 桌面上能用、游戏里不能用 → 游戏是独占全屏，改成无边框窗口模式

**截图是黑屏**

- 同上，改成窗口化。这条没有别的解法。

**悬浮窗看不见**

- 游戏独占全屏，改成窗口模式
- 悬浮窗默认 20 秒没新内容就自动隐藏，再按一次 `Ctrl+Alt+T` 就会出来
  （这个时间可以在 config.json 的 `overlay.auto_hide_sec` 改）

**双击「启动.bat」没反应**

- 双击「调试启动.bat」，错误信息会留在窗口里
- 如果提示找不到 pythonw.exe，说明 Python 装的位置和脚本里写的不一样，
  打开 `启动.bat` 把 `set "PYW=..."` 那行改成你的实际路径

**翻译出来是乱码**

- 不应该发生。SSE 的 UTF-8 解码是专门处理过的，如果真遇到了告诉我。

**提示"没有 API key"**

- 检查 `config.json` 里的 `api_key`，或环境变量 `GCT_API_KEY`
- 注意 key 别有多余的空格或引号

**显示"缓存命中"但内容不对**

- 极罕见（理论上不可能，缓存键含画面像素 hash）。遇到了告诉我。
